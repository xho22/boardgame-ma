# 规格介绍

## 1. 项目定位

`boardgame-ma` 是一个面向家庭和朋友聚会的轻量网页桌游。玩家不需要账号，也不需要联网建房；打开网页后选择玩家人数和每名玩家每场派出的 racer 数量，每位玩家获得一组奇幻选手。每场比赛前，玩家从自己的队伍中秘密选择 1 或 2 名选手参赛，随后场上所有 racer 轮流掷骰、移动棋子、触发能力。所有比赛结束后，总分最高者获胜。

本项目的目标不是商业发行，而是私人家庭游玩。因此玩法结构会尽量贴近实体桌游的节奏：简单的掷骰移动、强能力角色、混乱互动、短时间内产生笑点和反转。

角色名称、界面文案、美术表现和游戏标题全部使用原创内容。角色能力以“同效果、重命名、重写描述”的方式实现，避免直接使用原卡牌文本。

## 2. 第一版范围

第一版只做完整可玩的本地网页游戏。

### 必做

- 2 到 6 名本地玩家
- 玩家名称和颜色设置
- 无购买、无拍卖、无招募市场
- 开局自动给每位玩家分配一组角色
- 每场比赛秘密选择 1 名角色；2-3 人局可选择每名玩家每场 2 名角色
- 每名角色整局只能参赛 1 次
- 4 场比赛
- 横向赛道
- 掷六面骰移动
- 角色特殊能力
- 前两名冲线后结束比赛
- 每场比赛按名次发分
- 总分排行和最终胜利页
- 本地存档，刷新后可以继续
- 规则引擎与 UI 分离，预留未来在线房间同步

### 暂不做

- 在线多人
- 账号系统
- 玩家聊天
- 商店、购买角色、金币经济
- 复杂角色养成
- 排行榜
- 移动端真私密手牌

### 必须预留

- 固定房间模式
- 两个或多个终端同步同一局游戏
- 私密选择在各自终端完成
- 房主创建游戏，其他玩家加入
- 由服务器或房主统一推进权威游戏状态

## 3. 游戏核心规则

## 3.1 玩家人数

支持 2 到 6 人。

推荐人数：3 到 5 人。

不同人数会影响每位玩家获得的角色数量和比赛结算方式：

| 人数 | 每人每场 racer 数 | 每人角色数 | 比赛场数 | 每场奖励 |
|---|---:|---:|---:|---|
| 2 人 | 1 或 2 | 4 或 8 | 4 | 第一名、第二名 |
| 3 人 | 1 或 2 | 4 或 8 | 4 | 第一名、第二名 |
| 4 人 | 1 | 4 | 4 | 第一名、第二名 |
| 5 人 | 1 | 4 | 4 | 第一名、第二名 |
| 6 人 | 1 | 4 | 4 | 第一名、第二名 |

说明：默认节奏仍是每名玩家每场 1 名 racer、每人 4 名角色。2-3 人局可开启每名玩家每场 2 名 racer，让场上保持 4-6 枚棋子；此时每人获得 8 名角色，保证 4 场比赛每名角色仍只上场一次。每场只奖励前两名，让比赛更快结束，也让“第二名争夺”有意义。

## 3.2 开局分配角色

由于用户明确不需要购买角色功能，第一版采用自动分配。

分配流程：

1. 系统从角色池中随机抽取 `玩家人数 * 比赛场数 * 每人每场 racer 数` 名角色。
2. 按蛇形顺序分给玩家。
3. 每名玩家最终获得 4 或 8 名角色，取决于每人每场 racer 数。
4. 所有角色在玩家面前公开展示。
5. Teams 页面提供 `Randomize Teams`，可在开始选角前重新随机分配所有玩家的角色。

蛇形分配示例，4 名玩家：

```text
第 1 轮：A -> B -> C -> D
第 2 轮：D -> C -> B -> A
第 3 轮：A -> B -> C -> D
第 4 轮：D -> C -> B -> A
```

这样可以减少随机分配造成的明显不公平。

可选设置：

- 完全随机分配
- 蛇形公开分配
- 手动挑选角色

第一版默认：蛇形随机分配。

## 3.3 比赛场数

标准局固定 4 场。

每场开始前，所有玩家从自己的未使用角色中选择本局设置要求的 1 或 2 名 racer 参赛。选择后该角色本局不能再次上场，除非其能力明确允许。若每名玩家选择 2 名 racer，比赛的行动顺序、移动、冲线和能力触发都以 racer 为单位；积分仍归属其玩家。

## 3.4 赛道

第一版使用单条横向赛道。

默认长度：30 格。

位置定义：

- 起点为 `0`
- 终点为 `30`
- 角色位置大于或等于 `30` 时视为冲线

第一版先不启用特殊地形格，角色能力已经足够制造混乱。后续可以加入双面赛道和特殊格。

## 3.5 回合顺序

第一场比赛的先手：

- 随机决定。

后续比赛的先手：

- 上一场最后一名玩家成为新先手。
- 其余玩家按座位顺序继续。

如果上一场有未冲线玩家：

- 未冲线玩家中位置最靠后的玩家视为最后一名。
- 若仍平手，按距离先手更近者判定为更靠后名次。

## 3.6 掷骰移动

当前玩家点击掷骰按钮，得到 1 到 6 的结果。

UI 表现要求：

- 点击掷骰后，骰子区域先进入约 2 秒的滚动状态，数字在 1 到 6 间快速变化。
- 滚动结束后才展示规则引擎结算出的真实骰点。
- 真实骰点必须写入比赛日志。
- 比赛日志面向玩家显示中文文案，不直接暴露内部 id 或英文调试语句。

基础移动：

```text
最终移动值 = 骰子点数 + 角色能力修正 + 临时效果修正
```

移动值可以为 0，但不能为负数。若能力产生后退，则单独结算后退。

棋子表现要求：

- 所有会改变棋子位置的行为都必须有动画反馈，包括 main move、能力移动、后退、跟随、拉拽、换位、warp、箭头移动和冲线。
- 普通 move 和后退应该优先表现为逐格移动，让玩家看见棋子从原位置经过每一格到达目标格。
- warp、换位、淘汰等非连续位移也必须有明确视觉反馈，例如闪烁、淡入淡出或短暂高亮，不能无声改变坐标。
- 棋盘棋子优先使用角色头像，而不是玩家姓名首字母；同一玩家派出 2 名 racer 时必须能通过头像区分。
- trip 状态使用倒置角色头像表现，并配合轻微弱化或边框状态提示；恢复后头像恢复正向。
- 位置动画结束后，再进入下一步关键交互或展示下一条关键结果。

## 3.7 冲线与比赛结束

当角色移动后位置大于或等于终点，立即记录其名次。

已经冲线的角色：

- 不再行动
- 不再触发自身能力
- 不能再被其他能力选为目标

当第一名和第二名都产生后，本场比赛立即结束。

如果某个能力让比赛提前结束，需要能力自身明确声明。

## 3.8 积分

4 场比赛使用递增积分，让后期仍有翻盘空间。

| 比赛 | 第一名 | 第二名 |
|---|---:|---:|
| 第 1 场 | 3 | 1 |
| 第 2 场 | 4 | 2 |
| 第 3 场 | 4 | 2 |
| 第 4 场 | 5 | 3 |

如果 2 人局中只有一名角色冲线即因特殊效果结束，另一名玩家默认第二名。

## 3.9 终局

4 场比赛结束后，总积分最高者获胜。

平局规则：

1. 第一名次数更多者胜。
2. 第二名次数更多者胜。
3. 最后一场名次更高者胜。
4. 仍平局则共同胜利。

## 4. 能力系统设计

角色能力按触发时机实现。所有能力都应该通过统一接口处理，方便将实体卡牌能力逐个映射进网页游戏。

## 4.1 能力触发时机

```text
beforeReveal       公开选手前
afterReveal        公开选手后
beforeTurn         自己掷骰前
afterRoll          自己掷骰后、移动前
beforeMove         移动前
duringMove         移动过程中
afterMove          移动后
onPass             超过其他角色时
onPassed           被其他角色超过时
onShareSpace       与其他角色同格时
onAbilityTriggered 任意能力触发时
onFinish           自己冲线时
afterRace          比赛结束时
```

## 4.2 能力结算顺序

同一时点有多个能力可触发时，按以下顺序：

1. 当前行动角色的能力
2. 被移动、被超过或被影响角色的反应能力
3. 其他角色的全局监听能力
4. 临时状态结算
5. 冲线检查

如果多个非当前玩家能力同时触发：

- 从当前玩家的下一位开始，按座位顺序依次结算。

## 4.3 移动过程定义

为了实现“经过”“超过”“同格”等能力，移动不能只更新最终坐标，而要逐格模拟。

示例：

```text
角色从 3 移动到 8
路径为 4, 5, 6, 7, 8
每进入一格都检查：
- 是否经过某角色
- 是否与某角色同格
- 是否触发移动中能力
- 是否到达终点
```

后退移动同理，但后退不会触发“超过前方角色”，除非能力特别说明。

## 4.4 状态效果

第一版需要支持这些状态：

| 状态 | 含义 |
|---|---|
| skipNextTurn | 下次轮到该角色时跳过主移动 |
| cannotUseAbility | 暂时不能使用能力 |
| rerollAvailable | 可重掷一次 |
| copiedMovement | 复制某个点数或移动值 |
| attachedTo | 跟随另一个角色一起移动 |
| stunned | 本回合不能响应能力 |
| reversed | 本次移动方向反转 |

## 4.5 标准版术语

以下术语来自 `rules/terms.png`，后续规则引擎必须按这些定义实现。

| 术语 | 规则含义 |
|---|---|
| ahead / behind | 更靠近终点的是 ahead，更靠近起点的是 behind；同格时互相既不 ahead 也不 behind |
| alone | 该选手当前没有和其他选手同格 |
| last place | 当前最靠近起点的选手；可多人并列 |
| lead | 当前最靠近终点的选手；已冲线选手不再计入 lead；可多人并列 |
| main move | 玩家回合中固定获得的行动：通常掷骰并移动对应格数 |
| move | 选手因 main move、能力或明确写有 move 的效果而改变格子；移动 0 不算 move |
| passing | 某次 move 开始时在另一名选手 behind，结束时在其 ahead |
| sharing a space | 两名选手都已经停在同一格，才算 sharing；移动或 warp 过程中短暂经过同格不算 |
| space | 起点、赛道格和终点都算 space；终点之后不算 space |
| stopping on a space | 选手完成移动或通过能力到达某格并停下 |
| trip | 被 trip 的选手跳过下一次 main move；不掷骰，但能力仍可能触发，也仍可通过其他方式移动；trip 不会提前结束当前移动 |
| warp | 直接把棋子放到新格；warp 不算 move，不触发 passing 或基于 move 的能力 |

野性赛道特殊格：

| 格子 | 规则含义 |
|---|---|
| arrow | 停在箭头格时，按箭头数字和方向移动；这次移动是独立 move，不是抵达箭头的 main move 的一部分 |
| rock / trip | 停在石头格时 trip |
| star | 停在星星格时获得 1 个铜色 1 分筹码 |

细节规则：

- 重掷后，之前的掷骰视为没有发生，不触发能力。
- 起点算一个 space。
- 多名选手同时停在同一格时，基于“停在同格”的能力仍会触发。
- 移动 0 不算 move。
- 写有特定时机的能力，例如 before my main move，每回合只触发一次。
- 选手赢得名次或因其他方式离开比赛后，能力失效，除非能力另有说明。
- 如果一个效果允许重掷，只能重掷最近一次掷出的骰子。
- 无限循环只按发生顺序完整执行一轮后结束；但 Scoocher 与 Suckerfish 这类明确可多次互动的效果不自动视为循环。

## 5. 角色能力映射方案

为了满足“名字全部替换、技能保留”的目标，角色数据采用两层命名：

- `sourceKey`：内部映射编号，不在 UI 展示
- `displayName`：网页游戏中的原创角色名
- `abilitySpec`：效果实现
- `abilityText`：原创中文描述

示例：

```ts
{
  sourceKey: "standard_suckerfish",
  displayName: "影步学徒",
  standardName: "吸盘鱼",
  abilityText: "每当同格的其他选手移动时，你可以跟着移动到他的新位置；如果一起冲线，对方名次在你之前。",
  timing: ["onOtherEntrantMovesFromSameSpace"],
  implementation: "follow_same_space_mover"
}
```

## 5.1 标准版角色映射原则

本项目的目标是尽量还原用户手中的最新版规则。因此角色池必须以最新版实体卡牌或规则书为准，而不是凭旧版规则、评论文章或公开简介猜测。

每张角色应建立一条映射：

```text
标准版角色名 -> 网页原创角色名 -> 最新版能力要点 -> 代码实现 key
```

示例：

```text
吸盘鱼 -> 影步学徒 -> 每当同格其他选手移动时，可以跟随到其新位置；若同时冲线，目标名次在前 -> follow_same_space_mover
```

若某张卡的最新版能力尚未确认，则在文档中标记为 `待确认`，不得当作最终规则实现。

## 6. 用户流程

## 6.1 首页

首页直接进入游戏功能，不做宣传页。

元素：

- 游戏标题
- 新游戏
- 继续游戏
- 规则
- 设置

## 6.2 新游戏设置

玩家可设置：

- 玩家人数
- 玩家名称
- 玩家颜色
- 是否启用 AI
- 角色池规模：基础 12、标准 24、完整 36
- 是否显示能力详细提示

默认设置：

```text
玩家人数：4
角色池：标准 24
比赛场数：4
赛道长度：30
AI：关闭
```

## 6.3 队伍展示

开局后展示每位玩家的 4 名角色。

每张角色卡显示：

- 角色名
- 类型标签
- 能力描述
- 使用状态
- 角色头像

玩家可以点击角色查看详情。

## 6.4 秘密派遣

本地同屏无法真正隐藏信息，因此使用“传手机/遮挡”式流程。

流程：

1. 屏幕显示“请玩家 A 选择角色”。
2. 玩家 A 点击“我准备好了”。
3. 显示玩家 A 的可用角色。
4. 玩家 A 选择后点击“锁定”。
5. 屏幕显示遮挡页。
6. 传给下一名玩家。
7. 所有人选择完毕后统一揭示。

开发注意：

- 锁定后不能返回修改，除非开启“家庭宽松模式”。
- 遮挡页不能显示已选择角色。
- 儿童游玩时建议开启“公开选择模式”，减少操作麻烦。

## 6.5 比赛界面

比赛界面是核心页面。

布局：

- 顶部：比赛编号、奖杯分值、当前轮次
- 中部：横向赛道
- 下方：当前玩家行动区
- 右侧或底部：比赛日志

当前行动区包含：

- 当前玩家名
- 当前角色卡
- 掷骰按钮
- 可用主动能力按钮
- 跳过/确认按钮

主动能力交互要求：

- Legs：在主移动前显示“掷骰移动”和“直接移动 5 格”两个选择；选择直接移动时不播放掷骰动画。
- Flip Flop：主移动前显示可选目标和换位按钮；可以选择任意仍在比赛中的其他选手，也必须允许玩家放弃换位并正常掷骰。
- Cheerleader：在主移动前提供明确操作，选择“先支援最后一名再掷骰”时，先让最后一名移动 2 格，再让自己移动 1 格，然后正常掷骰。
- Genius：在掷骰前提供 `1-6` 的预测选择；若不预测，则视为放弃该能力。
- Hypnotist、Third Wheel：在 before main move 时提供是否使用能力的开关；启用后必须明确选择传送目标或目标格，不能由 UI 悄悄代选。
- Magician、Rocket Scientist：严格规则时机是掷骰后决定是否重掷/加倍。当前本地 MVP 可先使用回合开始前的策略开关，但在线多人阶段应升级为 after-roll pending prompt。
- Suckerfish：同格角色移动后必须弹出跟随确认；确认跟随后，这次移动同样进入经过、同格和后续跟随等结算，再继续本回合剩余流程。
- Dicemonger 等别人回合的反应能力，未来在线同步时应通过 reaction prompt 明确确认；本地 MVP 可暂用自动策略。
- Mastermind：揭示本场 racer 后、正式开赛前必须选择预测目标。目标是具体 racer，不是玩家；未选择时不能开始比赛。

赛道表现：

- 每名玩家一个颜色
- 棋子上显示角色头像缩写
- 同格时棋子错位叠放
- 已冲线角色移动到终点领奖区
- 棋子移动、后退、跟随、warp、换位、淘汰和冲线都必须有动画或高亮反馈
- trip 中的角色轮到行动时，当前行动区显示恢复状态，不显示掷骰按钮；约 3 秒后自动结算恢复并进入下一回合。

日志栏要求：

- 比赛界面必须始终能看到最近日志，桌面端在右侧或下方，移动端可以折叠但要容易展开。
- 每一步关键事件都要写日志，包括掷骰、移动、能力触发、状态变化、冲线、得分。
- 日志不仅记录“发生了什么”，还要说明“为什么发生”和“导致什么结果”。
- 多个能力连锁时，日志必须按结算顺序追加。
- 最新日志显示在最上方，但序号必须保留真实追加顺序；列表最多显示区域固定高度，超过后通过滚动查看历史。

## 6.6 赛后结算

显示：

- 第一名和第二名
- 对应玩家获得分数
- 总分变化
- 本场使用角色
- 下一场按钮

## 6.7 终局页面

显示：

- 冠军玩家
- 总排行榜
- 每场比赛结果
- 每名玩家角色使用记录
- 再来一局
- 回到首页
